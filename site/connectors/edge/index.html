Edge & OT connectivity

Every Shop-Floor Protocol, One Gateway

The Fuuz Device Gateway is a proprietary on-premise software agent that provides bidirectional communication between the Fuuz cloud and local industrial equipment — remote configuration, automatic updates, and store-and-forward during network interruptions. Every major MES, SCADA, historian, PLC, robot and industrial gateway platform is reachable through it, either with a native driver or a validated bridge.

Edge vs. cloud. This page covers on-premise and shop-floor integration — PLCs, SCADA, sensors, historians, on-prem databases. For cloud-based SaaS and enterprise application connectivity (ERP, CRM, eCommerce, AI), see IT & Cloud Connectors.

Featured — recently added

The Fuuz Ignition Module

Ignition is already the best protocol match for Fuuz of any industrial platform — every Fuuz driver connects to it directly over OPC UA, MQTT, Sparkplug B, Modbus, HTTP and SQL. The Fuuz Ignition Module goes a step further.

Lives inside the gatewayAdvanced

Rather than an external client polling Ignition's OPC UA server, the Fuuz module installs directly inside the Ignition Gateway itself — the same architecture pattern as any other Ignition Gateway module, running alongside Ignition's own OPC UA, Sparkplug and tag systems rather than in front of them.

Creates the subscription, not just the read

A generic OPC UA browse-and-subscribe client only ever sees tags. The Fuuz Ignition Module creates the Fuuz-side DeviceSubscription directly from inside the gateway, so tag discovery and subscription management happen where the tag data already lives, not from a second hop outside it.

Same platform, less to run

No separate OPC UA client process to deploy, monitor and restart alongside Ignition. One module, installed once, inside the gateway you already operate.
