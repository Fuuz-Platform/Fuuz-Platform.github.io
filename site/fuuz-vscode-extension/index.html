Fuuz for VS Code

Build and run Fuuz apps from VS Code with your AI assistant. Connect your tenants over MCP, explore and query their data, write specs and have agents build them, test flows on your machine, and check screens in a real, signed-in browser.

Open beta, free to use

Fuuz for VS Code is in open beta while our Engineering team builds the production version. It is free to use: install it, connect your tenants and put it to work. Expect it to change between versions, and tell us what you find.

Get started What it does

What it does

From Connection To Checked Screen

Everything below is in the extension today. Some of it depends on your Fuuz subscription and on what your Fuuz user is allowed to do; see Permissions.

Connect your tenants

Sign in with your Fuuz account on environments running Fuuz MCP V2, or add a tenant with an API key. The extension works with MCP V1 and V2 without configuration, and Test endpoints shows which of MCP, flow execution and webhooks each connection can reach.

Your AI assistant, connected

Registers the Fuuz MCP server for GitHub Copilot in VS Code, Claude Code and Claude Desktop, and for Codex and Gemini CLI accounts. Configs hold only a reference: keys stay in the Fuuz Secrets service, and a local proxy adds them to each request.

Explore and query

The Fuuz view lists each tenant's module groups, modules, screens, flows, data models, documents, scripts and GraphQL. The Model Explorer shows a model with its neighbors; the Data Query Console builds read-only queries and exports CSV or JSON. Ask @fuuz in chat, or work in Fuuz notebooks.

Specs, built by agents

Write a spec as requirements, design and tasks, approving each before the next. Start one task, or run them all in waves across several AI accounts (Claude Code, Codex, Gemini CLI, Copilot). Agents hand work off to each other, and the harness hook blocks their writes to production tenants.

Fewer platform mistakes

Every agent gets a guide to the mistakes agents make most on Fuuz, with the exact errors and fixes, plus the Fuuz help docs (lms.fuuz.com) and the published apps on marketplace.fuuz.com to start from. When a Fuuz call fails with a known error, the fix appears next to it.

Test flows before deploying

A local flow emulator runs a flow definition on your machine: JSONata and JavaScript transforms run for real, platform nodes return stub results, and each node's input and output is shown. Its lint catches mistakes that deploy fine but run wrong.

See screens for real

Preview a screen locally before you push it. Start UI Session opens one signed-in Chrome you log into once; your assistant drives it with Playwright or Chrome DevTools to check that screens render, bind and save.

Compare, check and promote

Compare 2 to 5 tenants, or a tenant and an exported package: components, setup data and access. A compare lint separates harmful differences from expected ones. Compliance checks cover models, flows and screens. Deploying and promoting stay off until you turn them on.

Secrets and local services

Named secrets live in an encrypted vault on your machine. Agents ask for them and use them through a broker without ever seeing a value. Declare the local services your app needs (Docker, npm, databases, gateways), then start, check and query them; databases are read-only by default.

Team kits and spend

Team kits give every developer's agents the same rules, skills and shared UI components. Usage & Spend shows tokens and cost by repo, spec and task, read from session logs on your machine; nothing leaves it.

Claude Code plugin

Using Claude Code without VS Code? The fuuz-sdk plugin, from the same repository, connects Claude Code to a tenant and adds /fuuz-sdk:doctor, /fuuz-sdk:new-app and /fuuz-sdk:add-tenant.

Get started

Connected In A Few Minutes

You need:

  • VS Code 1.101 or newer.
  • A Fuuz tenant: an API key for it, or a Fuuz sign-in on an environment running Fuuz MCP V2.
  • For the AI features, a Fuuz subscription that includes MCP and an AI assistant: Claude Code, GitHub Copilot agent mode, Codex or Gemini CLI.
  • For browser checks, an installed Chrome, Chromium or Edge, and Node.js.

Install the .vsix from the latest release:

$ code --install-extension fuuz-vscode-extension-<version>.vsixIt doesn't update itself: install each new release the same way.

  1. Connect a tenant

    Open the Fuuz view and choose Sign in with Fuuz or Add Connection by API Key. The extension works out the tenant, enterprise and environment, checks the connection, and loads the tenant.

  2. Restart your AI assistant

    The Fuuz MCP server is registered with Claude Code and Claude Desktop automatically, and with VS Code for Copilot. Claude loads MCP servers when it starts, so restart it once.

  3. Start building

    Ask your assistant about the tenant, or run Fuuz: New Spec… to plan a feature and have agents build it task by task. Fuuz: Manage Fuuz holds the rest of the setup: tenants, secrets, AI accounts, team kits and add-ons.

Permissions (important)

What Your Fuuz User Must Be Allowed

Connecting and listing the MCP tools needs no special access. Using them (loading the tenant, querying data, running flows) needs the Fuuz user behind your key or sign-in to be authorized in that tenant. Assign it a policy, or policy group, with at least the read and query actions for:

  • accessControl: environment and current-user info
  • configuration: module groups, modules, screens, the model catalog
  • dataModeling: data models
  • orchestration: data flows
  • any business modules whose data you want to query

Running flows, sending webhooks or deploying also needs the matching write and execute actions. Access is granted per tenant, in Fuuz, not in VS Code.

An API key keeps the permissions it was issued with. After changing a policy, issue a new key and use Replace API Key.

If the tools are listed but the tenant's application and data models stay empty, the user is missing a read policy. The Couldn't load some resources entry in the Fuuz view (and the Fuuz output channel) names the modules to grant.

Subscription

The Fuuz MCP server depends on your subscription. Without MCP, the AI features and loading the tenant's resources are unavailable; you can still add connections, run flows and send webhooks, as far as your key allows.

Privacy

  • Keys and secrets are never written to settings or MCP configs; they are kept in VS Code SecretStorage or the Fuuz Secrets service on your machine.
  • Telemetry is off unless you turn on fuuz.telemetry.enabled and VS Code's own telemetry is on. It never includes secrets, names, file contents, prompts or record data.
  • Usage & Spend reads only token counts, on your machine.
